# Google Play 출시 가이드 — 오늘의 우리 (Android)

패키지 `app.ourtoday` (변경 불가) · 버전 1.0.0 (versionCode 1) · minSdk 26 · targetSdk 36

## 0. 순서 한눈에

1. 업로드 키 만들기 → `keystore.properties` → AAB 빌드 (`./gradlew bundleRelease`)
2. Play Console 에서 앱 만들기 → 스토어 등록정보·정책 설문 채우기 (아래 복붙)
3. **비공개 테스트** 트랙에 AAB 업로드 → 테스터 **12명 이상, 14일 연속** 참여 (2023-11 이후 만든 개인 계정 필수 조건)
4. 14일 뒤 Play Console 에서 "프로덕션 액세스 신청" → 심사 → 출시
5. 출시되면 랜딩(`landing/src/config.ts`)의 `PLAY_READY=true` 로 바꾸고 재배포

## 1. 업로드 키와 AAB

```bash
cd mobile/android
# 비밀번호는 직접 입력 (다른 곳에 저장하지 말고 비밀번호 관리자에 보관)
keytool -genkeypair -v -keystore upload.jks -alias upload -keyalg RSA -keysize 2048 -validity 10000 \
  -dname "CN=Ourtoday, O=BuildUp, C=KR"
```

`mobile/android/keystore.properties` (git 에 안 올라감):
```
storeFile=upload.jks
storePassword=입력한_비밀번호
keyAlias=upload
keyPassword=입력한_비밀번호
```

```bash
./gradlew bundleRelease   # → app/build/outputs/bundle/release/app-release.aab
```

- Play 앱 서명(Play App Signing)을 기본값대로 사용 → Google 이 배포 키를 보관하고, `upload.jks` 는 업로드용
- `upload.jks` 를 잃어버리면 Play Console 에서 업로드 키 재설정 요청 가능 (배포 키는 Google 이 갖고 있어서 앱은 안전). 그래도 백업은 꼭

## 4. 비공개 테스트 (12명 · 14일)

1. Play Console > 테스트 > 비공개 테스트 > 트랙 만들기 → AAB 업로드
2. 테스터: 구글 그룹 또는 이메일 목록 (12명 이상). 테스터는 **옵트인 링크**로 참여 후 Play 스토어에서 설치
3. **14일 동안 12명 이상이 계속 참여** 상태여야 함 (중간에 빠지면 다시 계산될 수 있음)
4. 14일 후 대시보드 > "프로덕션 액세스 신청" (테스트 중 받은 피드백·변경 사항 질문에 답변)

## 5. 출시 후

- 랜딩 `PLAY_READY=true` → 재배포
- 버전 올릴 때: `app/build.gradle.kts` 의 `versionCode` +1, `versionName` 변경 → `bundleRelease` → 업로드
- 웹(Next.js)만 바뀌는 수정은 앱 재심사 없이 바로 반영됨 (웹뷰 구조의 장점)

## 6. 알려진 제약

- 카카오톡 앱으로 로그인 후 앱으로 돌아오는 흐름은 보장되지 않음 → 카카오 계정(아이디/비밀번호) 로그인 안내
- 서버↔Vercel 구간 HTTP (데이터 보안 설문 답변 시 참고). 서버에 HTTPS(예: Caddy + 무료 인증서, 도메인 필요) 적용 권장
